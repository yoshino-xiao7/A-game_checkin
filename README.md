# A-game-checkin

面向 Yunzai v3、Miao-Yunzai 与 TRSS-Yunzai 的多社区游戏签到插件。

一次绑定社区账号，自动发现游戏角色；每天统一签到，并用图片卡片展示账号、签到状态和实际获得的奖励。

> 当前版本：`0.0.1`
>
> 默认签到时间：每天 `09:00`（`Asia/Shanghai`）

## 功能

- 一个插件管理米游社、森空岛和库街区账号
- 绑定后自动发现账号下的游戏角色
- 新发现的角色默认开启每日自动签到
- 支持按游戏名称或游戏编号手动签到
- 支持单独开启、暂停和删除签到项
- 账号、游戏、帮助、签到结果均使用高清图片卡片
- 签到日志按日期保存，并记录实际获得的道具、数量与道具图片
- Cookie、Token、用户 ID 和设备标识使用 AES-256-GCM 加密存储
- 调度、重试、日志保留时间和社区开关均可配置

## 支持范围

| 社区 | 游戏 | 推荐登录方式 | 备用方式 |
| --- | --- | --- | --- |
| 米游社 | 原神、崩坏3、崩坏学园2、未定事件簿、崩坏：星穹铁道、绝区零 | 米游社 App 扫码 | Cookie |
| 森空岛 | 明日方舟、明日方舟：终末地 | 手机号 + 短信验证码 | Token |
| 库街区 | 战双帕弥什、鸣潮 | 手机号 + 极验 + 短信验证码 | Token / 登录 JSON |

社区接口或风控规则可能随官方调整而变化。如果登录或签到突然失效，请先更新插件并查看 Yunzai 控制台日志。

## 运行要求

- Node.js `>= 18.18`
- Yunzai v3、Miao-Yunzai 或 TRSS-Yunzai
- 机器人能够访问对应社区的官方接口
- 可以向用户发送图片；使用库街区手机号登录时，还需要支持私聊发送 HTML 文件

## 安装

在 Yunzai 根目录执行：

```bash
git clone https://github.com/yoshino-xiao7/A-game_checkin.git ./plugins/A-game_checkin
cd ./plugins/A-game_checkin
npm install --omit=dev
```

### 配置加密主密钥

插件不会明文保存登录凭证。首次使用前必须生成一个 32 字节主密钥：

```bash
node scripts/generate-key.js
```

将输出内容设置为运行 Yunzai 进程的环境变量：

```text
A_GAME_CHECKIN_MASTER_KEY=生成的密钥
```

PowerShell 当前会话示例：

```powershell
$env:A_GAME_CHECKIN_MASTER_KEY="生成的密钥"
```

Linux 当前会话示例：

```bash
export A_GAME_CHECKIN_MASTER_KEY="生成的密钥"
```

使用 PM2、systemd、Docker 或面板启动 Yunzai 时，请在对应的进程配置中持久化该环境变量。配置完成后重启 Yunzai。

> 请妥善备份主密钥。密钥丢失后，已经保存的凭证无法解密；未配置密钥时，插件会直接拒绝保存凭证，不会降级为明文。

## 快速开始

所有绑定操作都应在机器人私聊中完成。

### 米游社

发送：

```text
#绑定签到 米游社
```

机器人会生成登录二维码。使用米游社 App 扫码并在 App 内确认，插件随后会自动发现账号下的米游社游戏角色。

如果当前环境无法扫码，可以使用：

```text
#绑定签到 米游社 Cookie
```

### 森空岛

发送：

```text
#绑定签到 森空岛
```

按照提示依次输入 11 位手机号和短信验证码。登录成功后，插件只加密保存换取到的 Token，不保存手机号和验证码。

备用入口：

```text
#绑定签到 森空岛 Token
```

### 库街区

发送：

```text
#绑定签到 库街区
```

登录流程如下：

1. 在私聊中输入手机号。
2. 下载机器人发送的一次性 HTML 验证文件。
3. 在本地浏览器打开文件并完成库洛官方极验滑块。
4. 页面通过用户浏览器直接请求库洛官方接口发送短信验证码。
5. 回到机器人私聊并输入短信验证码。

该流程不要求机器人拥有公网 IP、域名、端口映射或内网穿透。一次性文件有效期为 10 分钟，机器人发送后会删除自身临时副本。登录成功后只加密保存用户 ID、Token 和设备标识，不把手机号、短信验证码或极验结果写入账号数据。

如果机器人所在适配器不能发送 HTML 文件，可以使用备用入口：

```text
#绑定签到 库街区 Token
```

## 命令说明

### 帮助与查询

| 命令 | 说明 |
| --- | --- |
| `#签到帮助` | 查看图片版帮助 |
| `#签到账号` | 查看已绑定社区账号、角色和账号编号 |
| `#签到游戏` | 查看全部游戏角色、游戏编号和自动签到状态 |
| `#签到目标` | `#签到游戏` 的兼容命令 |
| `#签到日志` | 查看今天的签到奖励卡片 |
| `#签到日志 今天` | 查看今天的签到奖励卡片 |
| `#签到日志 昨天` | 查看昨天的签到奖励卡片 |
| `#签到日志 2026-07-31` | 查看指定日期的签到奖励卡片 |

签到日志按业务日期归档，不按“最近多少条”截取。已经从社区接口取得奖励详情时，卡片会显示道具名称、数量和道具图片。

### 手动签到

| 命令 | 说明 |
| --- | --- |
| `#全部签到` | 立即检查并执行当前用户的全部签到 |
| `#签到原神` | 签到全部原神角色 |
| `#签到鸣潮` | 签到全部鸣潮角色 |
| `#签到 7` | 签到“游戏卡片”中的第 7 个角色 |
| `#签到7` | 与 `#签到 7` 相同 |

按游戏名称执行时，会签到该用户绑定的全部同名游戏角色；按编号执行时，只签到对应的单个角色。

手动签到不受自动签到开关影响，但仍会检查当天结果：已经签到成功的角色不会重复请求。手动执行完成后，会返回包含奖励道具的签到卡片。

当前支持的名称和常用别名包括：

```text
原神
星铁 / 崩铁 / 崩坏：星穹铁道
绝区零
崩坏3 / 崩坏三
明日方舟
终末地 / 明日方舟：终末地
鸣潮 / 鸣朝
战双 / 战双帕弥什
```

崩坏学园2和未定事件簿角色可以通过游戏编号手动执行。

### 自动签到管理

| 命令 | 说明 |
| --- | --- |
| `#开启签到 3` | 开启第 3 个游戏角色的自动签到 |
| `#关闭签到 3` | 暂停第 3 个游戏角色的自动签到 |

新发现的游戏角色默认开启自动签到。插件默认每天 `09:00` 执行，调度器每 10 分钟扫描一次到期任务，并通过日期幂等记录避免同一天重复成功签到。

### 删除账号

先通过 `#签到账号` 查看账号编号，然后发送：

```text
#删除签到账号 2
```

机器人要求确认时，请在 60 秒内回复：

```text
确认删除
```

账号编号只用于删除社区账号；游戏编号用于手动签到以及开启、暂停某个游戏。两种编号不要混用。

删除账号会删除对应的加密凭证、游戏角色和自动签到订阅。历史奖励记录仍按照日志保留策略到期清理。

## 图片卡片

插件当前提供四类图片卡片：

- 签到账号：展示社区、账号编号、游戏角色和统一签到时间
- 签到游戏：展示可操作的游戏编号、角色信息和启用状态
- 签到帮助：集中展示常用命令和编号用法
- 签到奖励：按社区和游戏展示签到状态、奖励道具、数量与道具图片

所有插件卡片底部署名为：

```text
Created By A-game_checkin 0.0.1
```

部分社区的历史记录没有返回奖励详情时，卡片会明确显示“历史记录未保存道具详情”，不会伪造奖励内容。

## 配置

默认配置位于 `config/default.json`。需要自定义时，请新建 `config/config.json`；该文件不会提交到 Git，并会与默认配置进行深度合并。

默认配置：

```json
{
  "scheduler": {
    "cron": "0 */10 * * * *",
    "defaultHour": 9,
    "timezone": "Asia/Shanghai"
  },
  "retry": {
    "maxAttempts": 3,
    "baseDelayMs": 1200
  },
  "storage": {
    "attemptRetentionDays": 90
  },
  "communities": {
    "miyoushe": {
      "enabled": true,
      "requestTimeoutMs": 15000
    },
    "skland": {
      "enabled": true,
      "requestTimeoutMs": 15000
    },
    "kuro": {
      "enabled": true,
      "requestTimeoutMs": 15000
    }
  }
}
```

例如，将签到时间改为每天 8 点、日志保留 30 天并关闭库街区：

```json
{
  "scheduler": {
    "defaultHour": 8
  },
  "storage": {
    "attemptRetentionDays": 30
  },
  "communities": {
    "kuro": {
      "enabled": false
    }
  }
}
```

修改配置后请重启 Yunzai。

## 数据与安全

- 登录凭证使用 AES-256-GCM 加密后保存在 `data/accounts.json`
- 签到角色、订阅与按日期归档的奖励记录保存在插件 `data` 目录
- `config/config.json` 和运行数据默认被 `.gitignore` 排除
- 业务日志不会记录 Cookie、Token、短信验证码或完整原始接口响应
- 登录验证码和极验都按官方流程由用户完成，插件不提供验证码绕过
- 远程图片仅允许从 HTTP/HTTPS 地址加载

更新、迁移或重装插件前，请同时备份运行数据和 `A_GAME_CHECKIN_MASTER_KEY`。只备份其中一项无法恢复已绑定账号。

## 常见问题

### 提示缺少 `A_GAME_CHECKIN_MASTER_KEY`

运行 `node scripts/generate-key.js`，把结果配置到实际启动 Yunzai 的进程环境中，然后完整重启进程。只在另一个终端临时设置环境变量不会影响已经运行的 Yunzai。

### 库街区收不到验证码

确认一次性 HTML 文件未超过 10 分钟，并使用系统浏览器打开。浏览器需要能够访问库洛官方接口和极验资源。完成滑块只代表通过人机验证，仍需等待页面提示短信发送成功后再回到机器人输入验证码。

如果当前 QQ 适配器无法发送文件，请改用 `#绑定签到 库街区 Token`。

### 验证码登录提示失败

请确认输入的是最新收到的短信验证码，没有包含空格或其他文字。多次发送验证码后，旧验证码通常会失效；遇到官方频控时请稍后重试。

### 游戏名称签到没有响应

先发送 `#签到游戏` 获取游戏编号，再使用 `#签到 <游戏编号>`。名称命令只识别上方列出的游戏和别名，编号方式最稳定。

### 卡片仍显示旧内容

确认源码和 Yunzai 实际加载的插件目录一致，然后重启 Yunzai。部分渲染器会缓存模板和静态资源，更新后需要完整重启。

### 签到成功但没有道具图片

只有社区接口返回奖励详情时才能展示真实道具。历史记录或部分接口只返回签到状态时，插件会保留文字说明。若真实道具图片加载失败，则显示独立的占位图，不会叠加到真实道具图上。

## 开发

运行测试和静态检查：

```bash
npm test
npm run check
```

主要目录：

```text
apps/                 Yunzai 命令入口
lib/communities/      米游社、森空岛、库街区适配器
lib/core/             账号、游戏发现与签到协调逻辑
lib/notification/     文本结果与通知格式
resources/            账号、游戏、帮助、奖励图片模板
scripts/              主密钥生成等维护脚本
test/                 自动化测试
config/default.json   默认配置
docs/design.md        设计与架构说明
CONTEXT.md            领域词汇与边界
```

新增社区时，应在 `lib/communities` 中实现独立适配器，并向核心层返回统一的账号、游戏和签到结果，避免把社区 Cookie、接口地址与错误码耦合到 Yunzai 命令层。
